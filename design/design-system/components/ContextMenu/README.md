Right-click on any branch or tag row and every Git operation that row supports opens in place, ordered by how often each is reached for: checkout and browser actions first, then the ref-to-ref operations (new branch, merge, rebase, reset, cherry-pick), then delete on its own between two dividers so it never sits next to something reversible, then history and comparison, then the sync group, then the two "create something new" actions last. `radius-md` and `shadow-md` mark it as a floating layer, the same pairing as any dropdown or popover — GitDesk has exactly one floating-surface treatment, never a bespoke one per menu.

Every row reserves the same 16px icon gutter whether or not that action has an icon (`Checkout`, `Checkout Tip Commit`, `Cherry-Pick` don't), so labels stay aligned in one column regardless. `Reset` carries a `▸` chevron instead of an icon-plus-arrow, meaning "opens a submenu"; `Delete` is the only row with a keyboard shortcut shown, right-aligned in `ink-secondary`. A hovered row is the familiar `accent-selected-bg` + `ink-inverse` pair used everywhere else in GitDesk, so a context menu never needs its own hover color.

Disabled items follow Git's real constraints, not a fixed list: `Pull`, `Push` and `Sync` disable together whenever the row is a remote-tracking ref rather than a local branch, since you don't pull, push or sync a ref that only mirrors a remote — you do that from the local branch tracking it. `Checkout`, the merge/rebase pair, `Cherry-Pick` and `Delete` disable when the row is already the checked-out branch, since none of them mean anything against yourself. The menu's two ref-relative labels — `Merge '<ref>' into '<current>'` and `Rebase '<current>' onto '<ref>'` — always name the row that was clicked and the branch HEAD is on, never a placeholder, so the exact operation is legible before it runs.
